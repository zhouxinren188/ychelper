# 事业部在线名额与升级入口维护说明

最后复查：2026-08-19

## 固定产品规则

- 在线名额按事业部计算。默认基础版/试用版 1 台、标准版 2 台、高级版 5 台，后台可提高 `max_sessions`。
- 名额已满时保护所有其他设备的有效会话，新设备不得自动顶替最早会话。
- 同一 `device_id` 重启只替换自己的旧 Token，不额外占名额。
- 客户端只有同时取得有效订阅状态和非空 `session_token` 才能进入主界面。
- 超限设备进入订阅窗口，显示在线数量，默认选择第一个能够增加名额的更高版本，并提供“重新检测在线名额”。
- 支付升级成功后自动重新检测；只有服务器成功签发会话才进入主界面。
- 正常退出调用 `/api/auth/logout` 主动释放当前 Token；异常退出由心跳租约回收。

## 服务端响应契约

名额已满时：

- `status=session_limit`，使尚未升级的旧客户端也不会无 Token 进入主界面；
- `subscription_status` 保留真实的 `active` 或 `trial`；
- `session_granted=false`、`session_reason=concurrent_session_limit`、`session_token=null`；
- 返回 `online_count`、`max_sessions`、`recommended_tier`，不得返回其他设备的 Token 或完整设备标识。

成功时返回真实订阅状态、`session_granted=true` 和新 Token。

## 心跳与释放

- 新客户端每 30 秒发送心跳。
- 服务端租约为 120 秒，兼容仍以 60 秒发送心跳的旧客户端。
- 服务端每分钟清理会话租约；支付订单仍按原来的 5 分钟频率清理，禁止因会话调整改变支付任务频率。
- 正常退出最多等待 1.5 秒完成主动释放；失败时不得阻止退出，由租约兜底。

## 发布与部署顺序

该功能同时修改服务器和 Electron 主进程，不能用渲染层热更新发布。

1. 先部署服务器。`status=session_limit` 可保证旧客户端安全落入原订阅窗口，不会无 Token 进入主界面。
2. 再发布新的完整客户端版本，提供明确超限提示、推荐升级和自动重试体验。
3. 未获得明确授权时不得部署服务器、修改版本号、构建或发布客户端。

## 必测场景

- 基础版 A 设备在线时，B 设备登录被拒绝，A Token 继续有效。
- 标准版已有两台时第三台被拒绝；高级版已有五台时第六台被拒绝且不再显示更高版本。
- 同一设备重启获得新 Token，自己的旧 Token 失效且在线数不增加。
- 旧租约超过 120 秒后，新设备可进入。
- 正常退出立即释放名额；重复退出保持幂等。
- 升级后有空位自动进入；升级后仍满额时继续停留在超限页面，不得误进主界面。
- 服务器先部署、旧客户端仍不进入无 Token 主界面。
